Pages your agent makes for you.

Ask your AI agent for a shopping list, a packing list, a trip plan or a small app. It makes the page, publishes it encrypted, and sends you a link. You open it on your phone, tick things off and add to it. Later the agent reads back what you changed.

The key is the part of the link after #. Browsers never send that part to a server, so the relays and storage servers only ever hold scrambled bytes. Whoever has the link can open the page, and nobody else can.

Want an agent to build you a whole website you edit yourself? That is a different job, with its own skill: nsite-clay-web-builder.zip. Or point the agent at llms.txt.

Set it up in one step.

It works with any agent that can run shell commands: Claude Code, Codex, Hermes Agent and others. It needs Node.js 18 or newer and nothing else. No account, no key of yours, no server to run. The skill is one zip file.

Download nsite-artifacts.zip

Claude Code or Codex: one command

curl -fsSL -o /tmp/nsite-artifacts.zip https://nsite-clay.cypherpunk.today/skills/nsite-artifacts.zip &&
unzip -oq /tmp/nsite-artifacts.zip -d ~/.claude/skills &&
node ~/.claude/skills/nsite-artifacts/scripts/artifact.mjs help

That unpacks the skill into your skills folder and checks that it runs. For Codex, use ~/.codex/skills instead of ~/.claude/skills. Start a new session afterwards so the agent sees the skill. The same tool also comes with the command line package: npx nsite-clay artifact help. In Claude.ai, upload the zip under Settings, Capabilities, Skills, if your plan lets the agent run code and reach the network.

Or paste this to your agent

Install the nsite-artifacts skill. Download https://nsite-clay.cypherpunk.today/skills/nsite-artifacts.zip
and unzip it into your skills directory, so that nsite-artifacts/SKILL.md exists
there. If you do not have a skills directory, unzip it somewhere permanent and
remember where it is. Then read SKILL.md and follow it whenever I ask for a list,
a plan or a small page I can open on my phone, share, comment on, or edit myself.
Check that it works with: node <that folder>/scripts/artifact.mjs help

Then just ask.

  • Make me a shopping list for Saturday that I can tick off on my phone: milk, bread, coffee, olive oil.
  • Put our trip to Lisbon on a page my partner and I can both edit. Delete it a week after we are back.
  • What is still left on the shopping list?
  • Build a small habit tracker I can use every day, and tell me on Sunday how the week went.
  • Share the packing list with npub1… so only they can open it.
  • I am done with the list, take it down.

The agent writes the page, the tool encrypts and publishes it. The model never handles a key: the key only exists inside the link the tool hands back. Every page has an expiry, 30 days unless you say otherwise.

Say what should be different.

Every page you can edit has a Comments button in its corner. Select some words and press Comment, or pick a part of the page, and type what you want changed. It is saved with the page. Then tell your agent you have commented: it finds each comment and exactly where it sits, makes the change, answers under the comment and marks it resolved.

You can also change the page yourself, in the browser. The agent keeps a copy of the page as it last saw it, so it can tell exactly what you changed and make the rest of the page fit.

Send the edit link to the people who should comment, because a comment is saved with the page. Whoever has only the read link can look but not comment.

Who can open it.

  • Anyone with the link. The default. There are two links: one to read and one to edit. Send the edit link to people who should change the page and the read link to everybody else.
  • Only certain people. Give the agent their npubs. The link then carries no key at all, and each person signs in with their own Nostr key to open the page.
  • Everyone. Only when you ask for something public, such as a page for your website. Then it is not encrypted.

Taking someone off a page they already have the link to means a new key, because they hold the old one. The agent does that for you: it moves the page to a new link and deletes the old one.

The padlock on the page.

Every encrypted page has a small padlock button in its bottom corner. Opened with the edit link, it shows both links ready to copy, when the page expires, and who else can open it.

From there you can add a person by their npub, or delete the page right away, without asking the agent.

Opened with the read link, it only offers the read link and the expiry date. A person who signed in as a member sees no links at all, so a page shared with named people does not leak into a link.

If two people save at the same moment, the second save is refused and that person is asked to reload. Nothing is overwritten.

It cleans up after itself.

  • One version. A save keeps the version it replaced for two days, because a gateway can go on serving that one from its cache, and then deletes it. A list ticked a hundred times ends up taking the space of one, and storage servers hold only what is in use.
  • Expiry. The page carries its end date, and the agent runs a daily sweep that deletes what is past it. Set that up once; the skill tells the agent how.
  • Delete means delete. From the padlock or from the agent, the page and every version of it are removed from the servers it was put on. A copy somebody saved on their own device stays theirs, but without the link it is unreadable.

Optional: a guard outside the model.

The tool already refuses to publish a page in the clear unless asked twice. If you want that out of the model's hands entirely, add the guard as a hook. It blocks any command that would publish publicly or with another tool, and any attempt to read the file that holds the page keys. For Claude Code, in ~/.claude/settings.json:

{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash|Read",
        "hooks": [ { "type": "command",
                     "command": "node ~/.claude/skills/nsite-artifacts/hooks/guard.mjs" } ] }
    ]
  }
}

Your servers are your choice too. By default the pages go to public relays and to nostr.download and blossom.yakihonne.com. To use others, write them into ~/.config/nsite-clay/artifacts/config.json. The same folder keeps the keys of every page the agent made, so keep it private and back it up if the pages matter.
