Press Save and three things happen.

  1. The page copies itself.

    It takes its own text and pictures as they are now and packs them into one file.

  2. The copy is stored.

    A storage server, called Blossom, keeps the file under a name made from its contents, so nobody can swap it quietly.

  3. One signed note goes out.

    It says: this address now shows that file. Relays pass it on. That note is the publishing.

Nothing in this is a server you run. Relays keep the note, Blossom keeps the file, and your browser does the rest. Who may edit the page is decided by a key, not by a line in somebody else's database. This page is one of those documents, and it saves itself the same way.

Rather use the command line?

# make a site and a key for it
npx nsite-clay init mysite

# publish it
npx nsite-clay deploy mysite --sec=nsec1…

# or sign through a remote signer
npx nsite-clay deploy mysite --bunker="bunker://…"

Your site is served at https://<npub>.nsite.lol/ and by any other NIP-5A gateway.

Most pages made this way will be built by an agent. Point yours at llms.txt, a brief written for exactly that. For a site that is already online, llms-edit.txt is the second one.

What it does not do.

  • One key writes the page. No shared editing and no per-visitor content.
  • Two devices editing at once will lose one side. There is no way to detect the clash.
  • The gateway is trusted for the first byte. Everything after it is checked by hash.
  • No server code. If your project needs a backend, this is the wrong tool.

Try it with a real key.

A live page is published under a throwaway key, and the key is public on purpose. Open it, press Sign in, paste the key, and edit. Your save rewrites that page for everyone, so treat it as a sandbox and never paste a key you care about into a page you did not publish yourself.
